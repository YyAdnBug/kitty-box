# Kitty Box 方案

把常用的文件处理放在一个原生 App 里：打包、解压、图片和视频转换、修图（去背景、AI 水印、画笔擦除、视频固定台标）。
结构照 Kitty Tools（`~/Desktop/yy/Codes/Tauri/kitty-tools-macos/macos`，`macos` 分支）：规矩以它的 `.cursor/rules/mac-native.mdc` 为底，下面只写 Kitty Box 自己的取舍。

**状态：2026-10-30 拍板，31 项「全部按推荐」**。拍板页 https://claude.ai/artifact/HtJqQ4iFqqpFnS1ZoZ5Gxw（本地 `macos/build/research/plan-2026-10-30/decisions.html`，不入库）。M0 骨架已做，进度见 §5。

## 1. 技术栈

- Swift 6 语言模式（访达扩展那个 target 例外，见 §2「访达右键菜单」），默认 `MainActor` + approachable concurrency；`@concurrent` 只给重活：解压 / 打包的子进程等待、图片编解码、模型推理、视频导出。
- macOS 15.0，`ARCHS = arm64`；Xcode 工程，构建设置全在 `Config/*.xcconfig`，pbxproj 的 target / project 层保持为空。
- Apple 框架：SwiftUI、AppKit、ImageIO、Core Image、Core ML、AVFoundation、UniformTypeIdentifiers、QuickLook（M6 加：空格快速查看）、Vision（M7 加：去背景、找文字水印）、AVKit（M8 加：视频预览和剪辑条）、FinderSync（M9 加：访达右键菜单的扩展，App 里只用它查扩展开没开、打开系统的扩展设置）。不写 Metal：Xcode 26 起 Metal 工具链要单独下载，每台编译的机器都得装（M3 实测）。
- 系统命令（经 `Shell/Subprocess.swift`，进程外）：`/usr/bin/tar`（bsdtar 3.5 / libarchive 3.7）。
- 记日志用系统的 `os`（`Logger`，subsystem `com.yy.kitty-box`，2026-11-02 加）：只记查 / 装更新没成、子进程退出码不是 0（程序名和退出码，不记参数：7zz 的 `-p` 带着密码）、访达扩展新建文件没成。
- **第三方：只有一个例外 `7zz`**（2026-10-30 拍板）。另有两份随包的数据文件，都不是代码依赖：LaMa 模型和 Gemini alpha 图。不建 SPM 包，不链接第三方库。

## 2. 各功能的做法

### 解压
- **zip 一律交给 bsdtar，其它格式交给 7zz**（2026-10-30 实测）：
  - 7zz 26.05 的 macOS 版解 Windows 打的 GBK 文件名 zip，会把名字弄坏并且丢字节（`报告/中文文件.txt` 变成 `/ļ.txt`），`-mcp=936` 不起作用；
  - bsdtar 加 `--options hdrcharset=GBK` 能解对。它也能用 `--passphrase` 解 AES-256 和 ZipCrypto 两种带密码的 zip。
- **编码判断**：`Archive/ZipNames.swift` 自己读 zip 中央目录（纯函数，单测锁住）。
  - 有 UTF-8 标志、或文件名字节本身是合法 UTF-8 的条目，按 UTF-8；
  - 没有标志、又不是合法 UTF-8 的，按 GBK；
  - 每次都把 `hdrcharset` 显式传给 bsdtar，不依赖子进程的 locale。
  - 不能一律按 GBK：系统 `ditto` 和访达打的 zip 写的是 UTF-8 字节，却不标 UTF-8 标志，实测如此。
- 7z / rar / rar5 / iso 等交给 7zz，带密码的 7z（包括连文件名也加密的）和 RAR 都能解。tar 一族（.tar、.tar.gz、.tgz 等）也交给系统 tar：7zz 解 .tar.gz 只解出一层 .tar。
  - 7zz 一律加 `-spd`：名字里的 `? * [` 不当通配符（原来解「Why?.7z」连旁边的「Why1.7z」也解）；在临时文件夹里跑、不用 `-o`（`-o` 里的 `*` 会被 7zz 换成包名，「a*b.7z」解到了别处，2026-11-02 实测）。
  - .rar、.7z 在 `Config/Info.plist` 里补了类型声明（`UTImportedTypeDeclarations`）：没装别的解压软件的 Mac 上 .rar 是谁都不认的类型，「打开方式」「服务」都不列本 App。
- 放进来就解；只有 App 自己的网址（访达扩展）交来的写「还没开始」、等你点「开始解压」（见「访达右键菜单」）。
- 有密码时弹框问，错了说「密码不对」再问，不留记录。跳过一个之后，后面要密码的照样问（原来跳过一次就再也不弹，2026-11-02）。
- **ZipCrypto 的错密码**：它只校验一个字节，错的密码有 1/256 混过校验、解到一半才因为数据对不上失败（报的是「Error exit delayed」不是「Incorrect passphrase」，2026-10-30 单测偶发失败查出来的）。所以中央目录里有加了密的条目（标志位第 0 位）、又解不成时一律当「密码不对」/「要密码」（`ponytail:` 真坏了的加密包也这么说）。
- **进度和停止**（2026-10-30）：7zz 加 `-bsp1`，进度写到标准输出（「 32% 6 + 名字」用退格隔开），取最后一个百分数；zip 走 tar 时加 `-v`（每解出一条在标准错误写一行），按行数 / 中央目录里的条数算；tar.gz 这类不知道总数，只转圈。`Subprocess` 每 0.25 秒看一次输出临时文件、交给调用方；任务被取消时 SIGTERM 子进程，解了一半的文件夹、打了一半的包删掉。解压的那一行和打包的状态栏有进度条 + 百分比 +「停止」，停下的那一行写「已停止」、能重试。
- **没给密码也要传一个占位的**（2026-10-30 实测）：tar 不给 `--passphrase` 会对着空的标准输入连问上万次，给空字符串它拒收；7zz 不给 `-p` 会卡在问密码。不加密的包会忽略它。按报错里的 `Incorrect passphrase`（tar）/ `Wrong password`（7zz）分出「要密码」和「密码不对」。
  - `ponytail:` 密码放在命令行上（只有同一个用户的进程看得到）。改从标准输入给反而坏：tar 遇到错密码会对着管道重试上万次（约 17 秒、留一个垃圾文件、也不写 `Incorrect passphrase`），放在命令行上 0.03 秒就报错（2026-11-02 实测）。
- **出错原因**（2026-11-02）只看标准错误（原来显示的是 7zz 满是退格的进度、tar 的「Error exit delayed」，或 `-v` 写的最后一行「x 名字」），认得的说成中文：坏了、不完整、分卷要从第一卷解、带 `../`、空间不够、只读、没有权限（不分大小写比）。坏的或恶意的 ZIP64 包（中央目录的位置加大小溢出）不再让整个 App 崩掉。
- **重试**：只动没解成的和等密码的（原来连解好的、正在解的一起重来），没解成的那一格就有「重试」；没解成的再拖进来就是重试。
- **看看里面**（M6）：右键「看看里面」（Esc 关）或双击还没解好的那一行，弹一张表：包里的文件（文件夹不算一项、解压时会跳过的杂文件不列）、各多大、一共多少。zip 自己读中央目录（名字按判断出的编码读，GBK 也对；大小在中央目录里，ZIP64 的大条目不另读、不写大小），tar 一族用 `tar -tf`（没有大小；加 `LC_ALL=en_US.UTF-8`：从访达打开的 App 没有 locale，中文名会印成 `\344\273\243`），别的用 `7zz l -slt`；连文件名都加了密的 7z 没输对密码时说「输入密码之后才能看」。
- 「解完移到废纸篓」开关（M5，页头的勾选框，默认关）：解好之后把压缩包挪到废纸篓（能放回去，不是删掉）；分卷包（.001、.part1.rar，旁边有 .z01 / .r00 的 .zip / .rar 也算）不挪，只挪一卷反而乱；挪不到废纸篓时那一行说一声。
- **分卷**（2026-11-02）：一整套拖进来只解一次，.002 起、.partN.rar 换成第一卷（原来几卷各报一次失败）。
- 解到压缩包旁边、与压缩包同名的文件夹里；如果包里只有一样看得见的真东西（文件夹或文件），就直接放出来，不再多套一层（比 B8 多了「单个文件」：`报告.docx.zip` 解出 `报告.docx`，同访达）；只有一个隐藏的（.git、.zshrc）或一个链接时照样放在文件夹里（放出来在访达里看不见，2026-11-02）。重名加「 2」。包旁边写不进去（磁盘映像、只读共享）时右键「解到…」选个文件夹。
- 先解到旁边一个隐藏的临时文件夹（`.<名字> 解压中`），去掉杂文件、做完再挪成正式名字；失败时删掉，不留半截。
- **隔离标记跟着走**：包带着「从网上下载」的隔离标记时，解出来的每样东西都带上（同系统的归档实用工具），不然包里的 App 打开时不会再被检查。

### 打包
- 用 7zz，只出 zip 和 7z 两种格式，默认 zip；压缩级别（M5）：存储 / 快 / 标准 / 最小 = `-mx0 / 1 / 5 / 9`，默认标准，记在偏好里：
  - zip：中文名会自动带 UTF-8 标志（已实测），7-Zip、WinRAR 都能正确显示；Windows 自带解压认不认这个标志，微软没有写明，M1 要在真 Windows 上试；
  - 7z：设密码时加 `-mhe=on`，连文件名一起加密。
- tar.gz 第一版不做。
- **选的东西可以来自不同的文件夹**（2026-11-02，同访达「压缩」）：按所在文件夹分组，7zz 在每个文件夹下各跑一次、加进同一个包，都在包的最上层；包放在第一样东西旁边。原来清单只写名字、7zz 只在第一个文件夹里找：要么整包失败，要么悄悄打进同名的另一个文件。
  - 不同文件夹里有同名的（不分大小写、合成形式）红字说明、按钮灰掉（7zz 会悄悄用一个盖掉另一个）；同一样加了两次、在已选文件夹里面的只算一次。打好之后再加东西是新的一批。
  - 分几组跑时任何一步出错，半个包都删掉。
- **怪名字**：7zz 一律加 `-spd`，名字里的 `* ? [` 不当通配符（原来选「Why?.txt」连「Why1.txt」也打进去）。清单带不了的名字放在 `--` 后面的命令行上：带换行或 `\r` 的（Icon␍）、两头有空格的、两头有引号的（7zz 读清单会去掉一行两头的引号，选「"q"」打进去的是旁边的「q」）。`ponytail:` 这种名字成千上万时会撞上约 1 MB 的命令行上限。
- **打包到…**（页头，存储面板）：自己选位置和名字。选了替换已有的包，旧的先挪到废纸篓（7zz `a` 会往旧包里加）；选的正好是要打进去的某个文件时不打，说「也在要打进去的东西里，换个名字或位置存包」（原来先把它挪进废纸篓、7zz 再说找不到）。
- 密码框旁边有个眼睛，点开看一眼（`ponytail:` 没有「再输一遍」：看得见就查得出输错）。在忽略清单的「加一条」里回车是加规则，不是打包。

#### 发给 Windows（B10、B11）
- **能不能开**（调研结果）：
  - 不带密码的 zip：Windows 自带解压能开；
  - 带密码的 zip：只有老式 ZipCrypto 自带能开，AES-256 的打不开；
  - 7z：Windows 11（2023-10 起，底层是 libarchive）自带能开不带密码的；Windows 10 要装软件；带密码的 7z 自带都打不开。
- **zip 的密码**：默认 AES-256。设了密码时，面板里多一个开关「让 Windows 自带解压也能打开」，打开后改用 ZipCrypto（`-mem=ZipCrypto`），并写明它容易被破解、重要的东西用 7z。开关状态存在偏好里。
- **Windows 不认的文件名**：`Archive/WindowsNames.swift` 是纯函数。检查三种情况：名字带 `\ : * ? " < > |`；结尾是空格或点；是 CON、PRN、AUX、NUL、COM1–9、LPT1–9 这类保留名。打包前在面板底部列出哪些文件有问题、为什么，不拦着打包，也不自动改名。

#### 忽略清单（B3–B6）
- **系统杂文件，默认勾上**：`.DS_Store`、`._*`、`__MACOSX`、`.Spotlight-V100`、`.Trashes`、`.fseventsd`、`.TemporaryItems`、`Icon␍`、`Thumbs.db`、`desktop.ini`、`$RECYCLE.BIN`。
- **开发目录，列着但默认不勾**（一键全勾）：`.git`、`.svn`、`node_modules`、`.venv`、`__pycache__`、`.idea`、`.vscode`。
- **自己加的规则**：按名字写通配符，可以用 `*` 和 `?`，路径里任意一层都算；以 `/` 结尾的只匹配文件夹；中间带 `/` 的不收。
- **存法**：一份全局清单，存在偏好里。打包页右边的选项栏里勾、加、删，改了就记住（没有设置窗，B5 说的「设置里也能改」就是这一栏）。
- **一套匹配，看到的就是打进去的**：`Archive/IgnoreRules.swift` 是纯函数，单测锁住。打包时自己遍历文件夹，用它筛一遍，把剩下的清单通过 `@listfile` 交给 7zz（每组在自己的文件夹下跑，清单里是相对路径；`-snl` 链接存成链接），不用 7zz 自己的 `-xr!`，免得两套匹配对不上。面板底部写「打包 N 个，忽略 M 项」（被排掉的文件夹算一项），点开能看到忽略了哪些、各是哪条规则排掉的。
  - 清单里写文件夹的话，7zz 会把它整个递归打进去，连被忽略的一起（`-r-` 也拦不住，实测）。所以只列本来就空的文件夹；里面只剩被忽略的东西的文件夹不列，它在包里就没了。
  - `._` 开头的附加信息文件，系统遍历文件夹时就跳过了（实测），不进清单，也不出现在「忽略了」里。
  - 匹配不分大小写，名字先统一成合成形式（访达给的常是分解形式）。
- **zip 的密码只能是 ASCII**：7zz 打 zip 时不收中文这类密码（报 `E_INVALIDARG`，实测），7z 没这个限制。打包页当场提示「要用中文密码请选 7z」，按钮不让点。
- **解压时也跳过**：`__MACOSX`、`._*`、`.DS_Store`（B7）。

### 图片转换
- 只用 ImageIO：
  - 读取（本机实测）：HEIC、WebP、AVIF、JXL、RAW、PSD、ICO 等；
  - 写出：JPEG、PNG、HEIC、AVIF、TIFF、GIF、BMP、ICO、ICNS、PDF。
- **预览**（M8，用户问「图片转换也不能预览吗」）：页面上半是选中那张的预览，转好了就是前后对比（右上「转换后」，能放大到 1:1 看画质差多少），下半是表格，中间能拖。换一张时不先露出上一张，解的时候又换了不盖回去，读不出写「读不出这张图」（原来一直留着或一直转圈，2026-11-02）。
- 支持批量转换（M5 起按核数几张一起转，最多 4 张：RAW、大图解码吃内存）；JPEG、HEIC、AVIF 有质量滑块（默认 85%）。换了格式、质量、尺寸、定位，转好的那些回到「等待中」。
- **转的时候能停**（2026-11-02，去背景、AI 水印同样）：页头主按钮换成「停止」（正在做的做完、没开始的留在「等待中」），右边选项锁住；转的时候移除的行不再转，连按两下只开一批。原来停不下来，改了选项转出和页头对不上的结果还标做完。
- **缩放和定位**（M5）：选项栏「尺寸」：原尺寸 / 长边 3840、2560、1920、1280、800（只缩不放，图标格式不管它；EXIF 里记的像素尺寸跟着改）；「隐私」：去掉定位信息（只去 GPS 那一组，拍摄时间、相机照样带；C3 当时说第一版不加开关）。
- 结果放在原图旁边、换扩展名，重名加「 2」；拍摄时间、相机、定位这些信息原样带过去（C3）。几张一起写时挑名字和占住一步完成（`FreeName.reserved()` 独占地建个空文件；原来 a.png、a.jpg 转 HEIC 都挑中 a.heic，后写的盖掉先写的，2026-11-02 复现过）；文件夹不能写时说「没有权限」。
- 照片的「旋转方向」标记 PNG、GIF、BMP 这些格式不认：一律按方向转正了再写，标记改成 1。解码走缩略图接口（为了转正），16 位、HDR 会变成 8 位（`ponytail:`）。

### 视频转换（M6）
- 新工具，侧边栏「转换」组（原来的「图片」组改名，图片转换和它一组）。一批视频，一个一个转（视频编码器就那么几路，一起转不见得快），每个有进度，页头「停止」取消正在转的、没开始的留着，停下旁边不留文件；转的时候右边选项灰掉（2026-11-02：原来转着时改了转成 / 尺寸，正在转的按旧设置做完却算做好）。

- 尺寸（只 MP4）：原尺寸 / 1080p / 720p / 480p，按短边算（横屏 720p 就是高 720，竖屏是宽 720），只缩不放，宽高取偶数；要缩时加一个视频合成按比例缩每一帧。
- GIF：每秒 10 帧、长边最多 480、最多取前 15 秒，一直循环（`ponytail:` GIF 没有帧间压缩，再长再大就上百 MB；要更长换 MP4）。在内存里拼好（最多几十 MB）再写到旁边：直接写到正式位置的话，停下时原视频旁边留一个藏起来的「.名字.gif-xxxx」（2026-11-02）。这些说明写在「转成」下面的小字里（原来是单独一张「说明」卡片）。

- **预览和剪一段**（M8，用户问「转换时不能预览吗」「要不要加截取」）：页面上半是选中那一行的预览，系统的播放器（AVKit `AVPlayerView`，同 QuickTime：播放、拖进度、逐帧），转好的能切到「转换后」看；「剪一段…」打开播放器自带的剪辑条（同 QuickTime 的「修剪」），点「修剪」就只转这一段（存在那一行的 `trim`，导出会话的 `timeRange`；GIF 从这一段的开头取，最多 15 秒——原来只能取前 15 秒）；「不剪了」回到整段；换了一段，转好的那一行回到「等待中」。上下两半中间能拖（`VSplitView`）。
  - 剪的那一段轮到那一个开始转时才取（2026-11-02：原来开始时就记下，转着时剪后面的不算数，却显示剪过、做好）；正在转的那一行不能剪（剪辑条开着时轮到它，再点「修剪」响一声、不记）；转好的结果没了，预览回到原视频。
- 一批文件的列表模型 `FileBatch`（原来叫 ImageBatch）：收什么由页面给（图片 / 视频），几个一起做，每个能报进度，`start` 开始的能 `stop`；`start` 马上记成在做（连按两下只开一批），做的时候移除的、还没开始的不做。

### 去背景（M7）

  - 底色取框边上两像素一圈的中位数；按到底色的颜色距离算透明度（从一圈里第 90 百分位的距离、至少 16，线性升到笔画第 95 百分位的距离；用线性不用 smoothstep，反混色才准），颜色反混出来：底色 +（像素 − 底色）/ 透明度，深底上也不带纸色毛边；

  - `ponytail:` 省略号那种虚线不在文字识别的框里，只有模型碰巧留下的才在；照片背景上的招牌字也会被留下（说明里写了，不想要就关掉）；很大的图上很小的字可能整张认不全。

## 7. 风险

- 不开沙盒，但 TCC 照样保护桌面、文稿、下载：第一次往这些文件夹写结果时，系统会弹窗问一次授权。
- Gemini 的位置规则一直在变（上游在 2026-05、06、08 都加过新变体），认不出来时要能退回到框选擦除。
- 7zz 和 bsdtar 的输出格式不是稳定接口：`Archiver` 只看退出码和少数几个固定的错误字样，比如 `Wrong password`。

## 8. 以后的 Windows 版（A6）

- 照 Kitty Tools，用 C# + WinUI 3 另写一套，放在 `windows` 分支。差异记在 `windows/MAC-DIFF.md`，开工时另起一张拍板页。
- **这份 PLAN 是行为的唯一来源。** 下面这些两边要一字不差：忽略清单的默认值和规则写法、结果文件的命名（`名字 2`、`-去水印`）、解压时跳过的杂文件。
- 各平台用自己的系统能力（待 Windows 版拍板时确认）：
  - 解压同样带 7-Zip（官方有 Windows 版）；
  - 图片用 WIC；
  - 模型用系统自带的 Windows ML 跑 ONNX 版 LaMa；
  - 视频用 Media Foundation。
- 中文 Windows 的默认代码页就是 936，7-Zip 解没标 UTF-8 的 zip 时自然按 GBK 处理，mac 这边的编码判断在 Windows 上用不着。
